# MCP 服务

AnyCode 统一管理 MCP 连接，通过 `mcp_discover` 和 `mcp_call` 动态工具提供发现与调用能力。接入支持本地 stdio 命令和 Streamable HTTP，不写入 Codex 配置文件。

## 配置与继承

- 全局设置的「MCP 服务」页签管理全局连接及默认开关，新增服务默认开启。
- 项目设置可覆盖同名全局服务，也可只修改继承服务的开关。项目定义整项替换全局定义，环境变量、请求头不会隐式合并。
- 卡片输入区的 MCP 按钮只控制该卡片的服务开关；未设置时跟随项目结果。上层关闭的服务仍可在下层单独开启。
- 移除本级设置会同时移除该层定义与开关，恢复上层结果；没有上层定义的服务随之消失。

命令参数每行一个，环境变量及 HTTP 请求头使用 `NAME=value`。本地命令在对应卡片工作目录执行。配置由现有访问密钥保护；环境变量和请求头的值不会在查询中回传，编辑时保留圆点可保留已存储的凭据。

## 运行行为

工具发现和调用每次读取当前配置。未启用服务不出现在发现结果中；即使模型保留旧的工具说明，后续调用仍会被拒绝。配置修改不打断已经开始的调用。

连接按卡片与服务隔离，配置或工作目录变化时重新建立连接。闲置连接在五分钟后由定时回收任务关闭；服务停止时统一关闭连接和本地子进程。连接检测使用独立连接，不占用卡片上下文。

工具发现超时为 15 秒，单次调用超时为 60 秒。支持分页工具发现、文本、图片、音频和结构化调用结果；HTTP 认证通过请求头配置。

## 验证

`make verify` 覆盖常规检查。MCP 测试包括全局/项目/卡片覆盖、关闭后的工具隔离、凭据脱敏与保留、数据库重载，以及本地假 MCP 的 stdio 和 HTTP 实际协议调用。
